# 03 · UX

---

## The two-surface doctrine

Reef has two working surfaces over the same data, one keystroke apart.

|  | **The List** | **The Reef** |
|---|---|---|
| Purpose | Do the work | See the shape |
| Answers | "Open the master lease" | "What's in here, and what haven't I touched?" |
| Speed | Instant, no WebGL, no animation over 200ms | Deliberate, cinematic |
| Default? | Yes, always | No — entered on purpose |
| Density | Maximum | Minimum |
| Required? | Yes | Never. Every datum is reachable without it. |

`Tab` toggles. Selection, filter and search state survive the toggle in both directions
— toggling is a change of *view*, never of *context*. Select three documents in the
list, press `Tab`, and those three organisms are lit.

**The rule that protects this:** if a piece of information can only be obtained by
entering the reef, that is a bug filed against the list.

**Why the reef exists at all.** A file tree cannot show that 200 of your 1,400
documents are one contract family, that a cluster of leases has no corresponding
insurance certificates, or that a third of the room is untouched two days before close.
Density, cluster, gap and connection are what 3D genuinely shows better than any list —
so the reef renders exactly those and nothing else.

## Global systems

### Keyboard model

Reef is keyboard-complete. Every action has a path without a pointer.

| Key | Action | Scope |
|---|---|---|
| `⌘K` | Command palette — everything, searchable | Global |
| `/` | Focus search | Global |
| `Tab` | Toggle List ↔ Reef | Room |
| `⌘⏎` | Ask the corpus | Global |
| `J` / `K` | Next / previous item | Any list |
| `⏎` | Open focused item | Any list |
| `Esc` | Close, cancel, ascend one level | Global |
| `E` | Jump to evidence for focused claim | Memo, answers |
| `[` / `]` | Previous / next evidence span | Document viewer |
| `F` | Flag as finding | Document, span |
| `R` | Mark resolved | Finding |
| `G` then `R` / `M` / `D` | Go to Rooms / Memo / Documents | Room |
| `?` | Shortcut sheet | Global |
| `⌘\` | Toggle side panel | Room |

`Esc` always ascends exactly one level and never discards typed input without asking.
In the reef, `Esc` rises one depth zone rather than exiting to the list — depth is the
hierarchy.

### State coverage

No surface is done until eight states exist: **loading, empty, partial, error,
stale, permission-denied, over-limit, unsupported.** Missing states are the most
common defect class in this kind of product and are treated as bugs, not polish.

### Error philosophy

Every error says what happened, why, and the one thing to do next. Never an error code
alone, never "something went wrong," never a retry button that retries a thing that
cannot succeed. When Reef fails on 12 of 1,400 documents, it processes the 1,388 and
names the 12 — partial success is reported as success with a named remainder, never as
failure.

### Accessibility baseline

Applies everywhere; per-surface notes below add to it.

- WCAG 2.2 AA. Text contrast ≥ 4.5:1 against the deep-water background, which is the
  main risk in a dark-first design — verify, don't assume.
- `prefers-reduced-motion` collapses all transitions to opacity fades ≤ 120ms and
  freezes all ambient motion, including the reef's currents and drift.
- Focus visible always, 2px `#3FE0D0` ring at 3:1 against any background it lands on.
- Live regions announce processing progress, finding counts, and answer completion.
- The reef is `aria-hidden` and carries a "Switch to list view" control as its first
  focusable child. Screen-reader users are routed to the list, which contains
  everything.
- No information conveyed by color alone. Severity carries an icon and a word.
- Targets ≥ 44px. Text resizes to 200% without loss.
- Captions on every marketing video, including the launch film.

# Surfaces

---

## 1 · Landing

**Purpose** Convince a searcher with 19 days left that this works and is safe to try.
**User goal** Understand what it does and see proof in under 40 seconds.
**Primary CTA** *Scan a room free* — 50 documents, no card.
**Secondary CTA** *Watch a 90-second run* — the real product, not the film.

**Interactions.** The hero is the launch film's shot 01 as a silent loop, poster-framed
so it holds even if video never loads. Scroll drives a single continuous descent
through five sections; the copy is pinned and the water moves. The live demo section
runs a real pre-loaded corpus — a question types itself, an answer appears, and the
evidence highlight scrolls into view on a real page. Nothing on the page is a mockup.

**Animation.** One idea: descending. Section transitions are depth changes, not slides.
Parallax across three layers at 0.6 / 0.85 / 1.0. Total scroll under 5 viewport heights;
long scrolljacked pages lose the buyer who is in a hurry.

**Microinteractions.** CTA gains a faint caustic sweep on hover, 400ms, once. Evidence
links in the demo highlight on hover exactly as they do in-product — the landing page
teaches the interaction it's selling.

**Loading** Poster frame + CSS gradient water; text is readable before any asset lands.
LCP under 1.8s on a cold 4G connection is a hard requirement, film or no film.
**Empty** n/a.
**Error** Video fails → still image, no broken frame. Demo backend down → pre-recorded
capture of the same interaction, labeled as a recording.
**Accessibility** Reduced motion gets a static hero and normal scrolling. The film is
decorative and `aria-hidden`; all claims exist as text.
**Keyboard** Fully tabbable, skip-to-content first stop, `⌘K` opens search on the docs.

## 2 · Authentication

**Purpose** Get out of the way while establishing that this is safe for confidential
deal documents.
**User goal** Be inside in under 15 seconds.
**Primary CTA** *Continue with email* — magic link. **Secondary CTA** Google SSO.

No password by default. A password is one more thing to leak, and the buyer is one
person, not an IT department. SAML arrives at M6 for buyers who require it.

**Interactions.** Email → link sent → in. The waiting screen states plainly where data
is stored, that documents are encrypted at rest, and that nothing is used for training.
That sentence belongs on the auth screen specifically, because it is the moment the
question is being asked.

**Animation.** Almost none. Surface-level light, calm, still. Auth is not where charm
belongs. Success: a single soft descent into the workspace, 600ms.
**Microinteractions.** Inline email validation on blur, never on keystroke. The submit
button shows a state, never a spinner replacing the label.
**Loading** Button label → "Sending…", disabled, 10s timeout with a plain fallback.
**Empty** n/a. **Error** "That link expired. Here's a new one." with the new one already
sent. Never make someone retype an address the system already has.
**Accessibility** `autocomplete="email"`, `inputmode="email"`, error tied by
`aria-describedby`, focus to the error on failure.
**Keyboard** `⏎` submits. Nothing else is needed.

## 3 · Workspace

The room list. Home after login.

**Purpose** Show every deal and its state at a glance.
**User goal** Resume the live deal — usually within two seconds of the page painting.
**Primary CTA** *New room* **Secondary CTA** Open the most recent room, which should be
so obvious it barely needs to be a control.

**Interactions.** Rooms as cards: name, document count, processing state, findings by
severity, days of exclusivity remaining if a deadline was set, last activity. Sorted by
activity. Search filters live. Archive on hover, never delete on hover.

**Animation.** Cards settle in on load with a 40ms stagger, 240ms each, translateY 8px.
Once. Not on every filter keystroke.
**Microinteractions.** Severity counts count up over 400ms on first paint only. The
deadline chip shifts from teal to warm amber under 5 days — the only warm color in the
product interface, so it means something.
**Loading** Skeleton cards at true final dimensions so nothing reflows.
**Empty** The teaching moment. One line — "Drop a data room here" — over a full-bleed
drop target, with a sample room ("Meridian HVAC, 1,412 documents") that opens a fully
processed real corpus. Let them see the finished thing before uploading anything of
their own.
**Error** Load failure keeps the shell, shows an inline retry on the list only.
**Accessibility** Cards are links, not click-handlers on divs. Grid is a list with
count announced. Deadline urgency is a word, not a color.
**Keyboard** `J`/`K` move, `⏎` opens, `N` new room, `/` filters.

## 4 · Upload

**Purpose** Get a messy folder in with zero decisions.
**User goal** Hand over the mess and stop thinking about it.
**Primary CTA** Drop anywhere. The whole surface is the target.
**Secondary CTA** *Paste a share link* — Drive / Dropbox / VDR URL.

**Interactions.** Drag anywhere on the window. Folders keep their structure — the
seller's folder names are evidence about how the seller thinks and are preserved. ZIPs
expand server-side. Duplicates are detected by hash and folded, not uploaded twice.
Nothing is asked before upload begins: no type selection, no tagging, no naming. Reef
infers and lets the user correct later.

**Animation.** On drop, files become points of light that fall into the water and sink
out of frame. The reef metaphor's first appearance, before the reef itself exists —
this is the one place pre-M4 where the world shows through, and it costs nothing
because it's 2D canvas particles.

**Microinteractions.** Per-file rows appear as accepted, with a checkmark on hash
completion. Count ticks live. Unsupported files stay in the list, greyed, with the
reason inline — never silently dropped, because a silently dropped file is a document
the buyer thinks was reviewed.
**Loading** Real per-file progress, aggregate throughput, honest time remaining
computed from observed rate. Never a fake progress bar — that is precisely the sin
DataGate was built to correct.
**Empty** Large calm drop zone, formats listed plainly, size ceiling stated up front.
**Error** Per-file, never global. "14 of 1,400 could not be read" with the 14 listed,
their reason, and a re-upload control for those alone. The other 1,386 proceed.
**Accessibility** A real `<input type=file>` behind the zone. Drag is never the only
path. Progress in a live region, throttled to every 10% so it doesn't flood.
**Keyboard** `⌘U` opens the picker from anywhere in the room.

## 5 · Processing

**Purpose** Make a 20-minute wait legible and worth watching once.
**User goal** Know it's working, know when it's done, leave and come back.
**Primary CTA** *Start asking* — enabled the moment the first document is queryable,
not when the batch finishes.
**Secondary CTA** *Notify me when complete* — email, one click.

**Interactions.** A live pipeline: read → OCR → structure → embed → connect → check.
Documents flow through visibly, counts climbing per stage. Failures pool visibly at
their stage rather than disappearing. **Results are usable progressively** — search
works over what's indexed so far, clearly labeled "searching 312 of 1,400."

**Animation.** Particles flow left to right through the stages at a rate proportional to
actual throughput, so the animation is a readout, not decoration. When a stage stalls,
the flow visibly slows. This is the single best animation in the product because it is
telling the truth.

**Microinteractions.** Stage completion pulses once. First document indexed triggers a
one-time toast: "You can start asking." The OCR stage shows a live confidence average;
under 70% it surfaces a note that scans are poor and answers from them are less certain.
**Loading** This surface is the loading state. It must be good enough to watch once and
boring enough to leave.
**Empty** n/a.
**Error** Never blocks. Failures accumulate in a "12 documents need attention" tray,
openable at any time, resolvable after processing completes.
**Accessibility** Live region announces stage completion and final counts, not every
document. Motion-reduced mode shows counters and bars, no particles.
**Keyboard** `Esc` leaves; processing continues. Nothing about leaving should feel like
cancelling — say "keeps running in the background" explicitly.

## 6 · Search & Ask

The working surface. The one that must never be slow.

**Purpose** Answer a question with evidence, or say the corpus doesn't contain it.
**User goal** Find the clause and see it on the page.
**Primary CTA** The input. Always focused on entry.
**Secondary CTA** *Add to memo* on any answer.

**Interactions.** One input, two modes it chooses itself: short keyword-shaped queries
run literal search; questions run retrieval and synthesis. Answers stream with citation
chips appearing inline as their support is bound — a chip never appears before the span
behind it is resolved. Hovering a chip previews the page; clicking splits the view to
the document at the highlight. `[` and `]` walk the evidence.

Filters: document type, date, folder, confidence, OCR quality. Results show why they
matched.

**Animation.** Minimal by mandate. Answer text streams, citations fade in at 120ms, the
split view slides at 180ms. Nothing else. This surface is used a hundred times a session
and any charm becomes an irritant by the twentieth.

**Microinteractions.** Chip hover raises the page preview in 80ms. Copying an answer
copies the citations with it as footnotes — the answer stays defensible after it leaves
Reef. Empty results offer the nearest queries that *would* return something.
**Loading** Answer skeleton with the retrieved sources listed first, so the user sees
what it's reading before it speaks. Retrieval under 400ms, first token under 1.2s.
**Empty** First visit shows five real questions drawn from this corpus's actual content,
not generic examples.
**Error** "Nothing in this room supports an answer to that" is a first-class result with
its own design — a bordered card, the searched scope stated, and suggested rephrasings.
It must not look like a failure, because it is the most trustworthy thing Reef does.
**Accessibility** Answers in a polite live region announced on completion, not per
token. Citation chips are buttons with text labels ("Evidence: Master Lease, page 14"),
never bare superscripts.
**Keyboard** `/` focus, `⌘⏎` ask, `E` first evidence, `[`/`]` walk, `⌘⇧M` add to memo.

## 7 · The Reef

The 3D view. M4.

**Purpose** Show the shape of a corpus — density, clusters, connections, gaps, and what
remains untouched.
**User goal** Orient. "What is in here, and where haven't I been?"
**Primary CTA** *Dive into a cluster* — click any formation to filter the list to it.
**Secondary CTA** `Tab` back to the list.

**Interactions.** Organisms by type (`04-visual-and-world.md`). Depth encodes
abstraction: findings and answers float high, documents sit mid-water, raw pages and
cells rest on the floor. Descending is drilling into evidence.

Untouched regions render dark and unlit; opened ones glow. Two days before close, the
dark part of the reef is the most useful image in the product. Connections render as
filaments — shared entities, cross-references, contradictions. Contradictions are the
only red in Reef.

Selection syncs both ways with the list. Search from inside the reef dims non-matches
rather than hiding them, so absence stays visible.

**Animation.** Camera language in `04`. Movement is drift and glide, never snap. Click a
formation and the camera eases to it over 900ms with a slight overshoot, then settles.
Ambient life continues at all times at low amplitude, so the world is never frozen.

**Microinteractions.** Hover raises a label card after 200ms — enough delay that sweeping
the cursor doesn't strobe labels. Newly ingested organisms bloom in once. Resolving a
finding dims its marker permanently, which makes progress visible as the reef quieting
down.
**Loading** Progressive: water and light first, formations by importance, detail last.
Interactive under 2s even if detail is still arriving.
**Empty** An empty room is open water with a single shaft of light and one line: "Nothing
here yet." Genuinely beautiful, and it should make someone want to fill it.
**Error** WebGL unavailable, context lost, or frame rate under 24fps for 3 seconds →
automatic fall back to the list with a plain, non-apologetic explanation and a manual
retry. Never trap someone in a broken world.
**Accessibility** `aria-hidden`, first focusable child is "Switch to list view."
Reduced motion freezes currents and drift and replaces camera eases with cuts. A
low-power mode ships with the same information at a fraction of the particle count.
**Keyboard** `Tab` exits, arrows orbit, `+`/`-` change depth zone, `Esc` ascends one
zone, `F` frames the selection. Every one of these is a convenience — none is the only
route to anything.

## 8 · Room (project) detail

**Purpose** The home of one deal: state, findings, documents, memo.
**User goal** Know what's been found, what's left, and how long remains.
**Primary CTA** *Open memo* **Secondary CTA** *Ask a question*

**Interactions.** Header carries name, deadline, document count and completion. Findings
list grouped by severity, each collapsible into evidence. Filters by status
(open / resolved / dismissed) and assignee. The completion meter measures *reviewed*
documents, not processed ones — the distinction is the honest one and users notice
immediately which one you chose.

**Animation.** Severity groups expand at 200ms with height transition. Nothing on load
beyond a 180ms content fade.
**Microinteractions.** Resolving a finding strikes it and moves it after a 2s undo
window — never immediately, never with a confirm dialog. Deadline chip warms under 5
days. Copying a finding copies its evidence links.
**Loading** Header and counts first from cache, list streams after.
**Empty** Processing complete, no findings: "Nothing on the checklist flagged in these
1,412 documents" with the checklist shown and every item marked checked. A clean result
must prove it looked, or it reads as a failure.
**Error** Per-section. A failed findings load never blanks the document list.
**Accessibility** Severity by icon + word + color. Groups are `<details>` semantics with
counts in the summary.
**Keyboard** `J`/`K`, `⏎` expand, `F` flag, `R` resolve, `G M` memo, `G D` documents.

## 9 · Settings

**Purpose** Control account, data, billing, and retention without a support ticket.
**User goal** Usually one of two things: change billing, or delete data.
**Primary CTA** Contextual per section. **Secondary CTA** *Export everything*

**Interactions.** Flat sections, no nesting: Account, Rooms & retention, Team, Billing,
Data & privacy, Shortcuts. Data & privacy states in plain sentences what is stored,
where, for how long, and what is never sent to a model provider. Deletion is real,
immediate, irreversible, and honest about backup windows.

**Animation.** None beyond focus transitions. Settings is the least appropriate place in
software for delight.
**Microinteractions.** Changes save on blur with a quiet inline "Saved" — no save button,
no toast. Destructive actions require typing the room name, never a bare "Are you sure."
**Loading** Real values or skeletons. Never a default value that might be wrong — showing
the wrong retention period for 300ms is a trust failure.
**Empty** No team yet → the invite control is the whole section.
**Error** Inline, per field, with the previous value preserved and restorable.
**Accessibility** Real fieldsets and legends. Destructive confirmations get
`role="alertdialog"` with focus trapped and restored on close.
**Keyboard** `⌘K` jumps to any setting by name, which for most users replaces navigating
here at all.

## 10 · Team

**Purpose** Get a second person into the room with the right access.
**User goal** Invite an analyst or an investor and split the work.
**Primary CTA** *Invite* **Secondary CTA** *Copy view-only link*

**Interactions.** Three roles, no matrix: **Owner** (billing, deletion), **Editor**
(everything except billing), **Viewer** (read, comment, no export). Invite by email or
link with expiry. Presence shows who is in the room and on which document. Findings
assign to people; comments anchor to spans and travel with the evidence.

**Animation.** Presence avatars fade in at 200ms. A cursor on a shared document moves
with a 120ms ease so it reads as a person rather than a network event.
**Microinteractions.** Invite link copies with a 1.5s inline confirmation and a stated
expiry. Assigning a finding shows the assignee immediately and reconciles quietly on
server confirmation.
**Loading** Optimistic. An invite appears as pending instantly.
**Empty** "You're the only one here" with the invite field focused and a sentence about
what a Viewer can and can't see — the question every user asks before inviting an
investor.
**Error** A bounced invite says so, keeps the address, offers a resend.
**Accessibility** Presence announced once on join, never per movement. Role changes
confirmed in a live region. Comment threads are landmarks.
**Keyboard** `⌘⇧I` invite, `@` mention in any comment.

## 11 · History

**Purpose** Make everything that happened replayable and defensible.
**User goal** "What did we ask, what did it say, and who exported what?"
**Primary CTA** *Re-run* on any past question against the current corpus.
**Secondary CTA** *Export the log*

**Interactions.** Chronological, filterable by person, type and date. Every question,
answer, finding change, export and share is an entry. Answers are stored with the
evidence they cited *and the corpus version they ran against*, so an old answer can be
read as it was, not as it would be now.

Re-running an old question against a newer corpus shows both answers side by side with
the difference marked. That is the feature that makes History more than an audit log.

**Animation.** None. This is a log and should feel like one.
**Microinteractions.** Entries expand in place. A changed re-run marks the delta inline.
**Loading** Paginated, 50 at a time, infinite scroll with a real end.
**Empty** "Nothing has happened in this room yet."
**Error** Partial load shows what loaded with a clear boundary marker.
**Accessibility** Real `<time datetime>`. Table semantics, sortable headers with state
announced.
**Keyboard** `J`/`K`, `⏎` expand, `⌘F` filter.

## 12 · Versioning

**Purpose** Handle the room changing under you mid-deal.
**User goal** "They just uploaded 200 files. What changed and does it break anything?"
**Primary CTA** *Diff against previous version* **Secondary CTA** *Re-run the checklist*

**Interactions.** Every upload batch creates a version. The diff shows added, removed,
and — the valuable one — **modified** documents, matched across versions by content
similarity rather than filename, because sellers rename constantly. Modified documents
show a span-level diff of the actual clause text.

Findings carry forward with state: still present, newly resolved by the new documents,
newly raised, or **invalidated because the underlying document changed**. That last
category is the one that ruins deals when it's missed by hand, and it is the reason this
surface exists.

Re-runs process only what changed. A 200-file addition takes minutes, not the original
twenty.

**Animation.** Diff rows expand at 200ms. Added / removed / modified are marked with
glyphs and words, and color is a third signal only.
**Microinteractions.** Version switcher shows document count and date. Hovering a
changed clause shows the previous text inline without navigation.
**Loading** Diff computes in the background with progress; the version list is instant.
**Empty** One version only: "This room hasn't changed since it was uploaded," with the
current version's stats. Not an error, not an invitation.
**Error** Diff failure falls back to a plain added/removed list by hash, which always
works, and says that's what it's showing.
**Accessibility** Never color alone — every change type has a glyph and a word.
Side-by-side diffs are linearized in a single column on narrow viewports and for screen
readers.
**Keyboard** `⌘⇧V` version switcher, `J`/`K` through changes, `D` toggle diff detail.

## Cross-surface notes

**The three-second rule.** From anywhere, a user reaches any document, finding, or
answer in under three seconds via `⌘K`. If a surface can only be reached by clicking
through two others, it needs a command-palette entry.

**Nothing modal that isn't a decision.** Processing, uploading, and asking all continue
while the user does something else. The only modals in Reef are destructive
confirmations.

**Deep-linkable everything.** Every document, page, span, finding, answer and version has
a URL. The most common sharing action in this product is pasting a link into an email to
someone who doesn't have an account, and that link must land them on the exact
highlighted clause behind a view-only gate.
